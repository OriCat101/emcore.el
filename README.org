* emcore.el
Emacs client for the emcore ERP (=erp.emotions.ch=) REST API: org-mode
ticket blocks, TRS time tracking mirrored from org-clock, and time
analysis reports.

** Setup
*** Credentials
Add an auth-source entry (e.g. =~/.authinfo.gpg=):

#+begin_example
machine erp.emotions.ch login you@emotions.ch password ...
#+end_example

The API has no machine auth --- =emcore-login= replays the browser flow:
password login, then the emailed 6-digit MFA token (prompted in the
minibuffer). With =emcore-save-device= (default =t=) a 30-day
trusted-device cookie skips MFA on later logins. Cookies persist via
url.el's cookie store, and any API call that finds its session expired
re-runs the login automatically.

*** Configuration
#+begin_src elisp
(require 'emcore)
(require 'emcore-org)
(emcore-org-clock-mode 1)

;; defaults:
;; (setq emcore-base-url "https://erp.emotions.ch")   ; or erp.test / erp.devlocal
;; (setq emcore-timezone "Europe/Zurich")
#+end_src

** Org blocks
Refresh any block with =C-c C-x C-u= (=org-dblock-update=), or insert
one with =M-x emcore-insert-ticket-block= /
=M-x emcore-insert-analysis-block=.

#+begin_src org
,#+BEGIN: emcore-ticket :no 1234
,#+END:
#+end_src

Renders the ticket's status, priority, assignee, firm/project, dates,
progress and effort, its description, and the full comment/change
history (scraped from the ticket page --- there is no API endpoint for
it). =:comments nil= skips the history and its extra page fetch.

#+begin_src org
,#+BEGIN: emcore-analysis :start "2026-09-01" :end "2026-09-30" :days t
,#+END:
#+end_src

Expected/worked/holiday/leave summary with balance; =:days t= adds a
per-day table. Dates are inclusive local dates and default to the
current month so far. =:user "<userId>"= reports on someone else (needs
the =trs-report= permission).

** Time tracking
With =emcore-org-clock-mode= enabled, give a headline (or an ancestor)
an =EMCORE_TICKET= property holding the ticket number:

#+begin_src org
,* Fix flux capacitor
:PROPERTIES:
:EMCORE_TICKET: 1234
:END:
#+end_src

- =org-clock-in= creates a running working-time entry linked to the
  ticket, with the headline as its comment
- =org-clock-out= stops it
- =org-clock-cancel= deletes it

To track time without a ticket, set =EMCORE_TRACK= (also inherited) to
any value except =nil= / =no= / =off=:

#+begin_src org
,* Meetings
:PROPERTIES:
:EMCORE_TRACK: t
:END:
#+end_src

The entry id is kept in an =EMCORE_TRACKING_ID= property while running.
If another entry is already running server-side, you are asked whether
to stop it.

Standalone (no org needed): =emcore-clock-in= (with ticket completion;
leave the prompt empty for an unlinked entry), =emcore-clock-out=,
=emcore-comment= (set the running entry's comment), =emcore-break=
(record a past break interval).

** API notes
Full API reference: =~/roam/20260902124805-emocore_api.org=. Highlights
the package builds on:

- every JSON response is the ={error, messages, data}= ColdBox envelope;
  errors signal =emcore-api-error= carrying the stable =data.error= code
- an expired session answers with the HTML login page, not a 401 ---
  detected and recovered transparently
- TRS timestamps are =yyyy-MM-ddTHH:mm= in UTC without a =Z=; analysis
  ranges are full ISO with exclusive end
- there is no endpoint listing time trackings; the running entry is
  recovered from =/trs/analysis/days= when needed
